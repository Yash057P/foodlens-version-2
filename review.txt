# 2. The biggest technical issue: your model-selection argument

This is probably the first thing a reviewer will notice.

You write:

> “EfficientNetB0 was ultimately selected ... as it provided the optimal trade-off between inference latency ... and Top-1 accuracy.”

But Table IV shows:

* DenseNet121: **74.20% Top-1**
* EfficientNetB0: **73.85% Top-1**

So DenseNet121 actually has **higher accuracy**. 

That means you cannot call EfficientNetB0 the “optimal” choice unless you provide the other side of the trade-off.

### What needs to be added

Add a table such as:

| Model          | Parameters | Model Size | CPU latency | RAM |     Top-1 |     Top-3 |
| -------------- | ---------: | ---------: | ----------: | --: | --------: | --------: |
| Custom CNN     |        ... |        ... |         ... | ... |     41.32 |     62.15 |
| ResNet50       |        ... |        ... |         ... | ... |     72.51 |     87.90 |
| MobileNetV2    |        ... |        ... |         ... | ... |     70.15 |     86.42 |
| DenseNet121    |        ... |        ... |         ... | ... | **74.20** | **89.10** |
| EfficientNetB0 |        ... |        ... |         ... | ... |     73.85 |     88.44 |

Then state something like:

> “DenseNet121 achieved the highest classification accuracy, while EfficientNetB0 offered a slightly lower accuracy with reduced computational cost and inference latency. EfficientNetB0 was therefore selected for deployment.”

That is a **defensible engineering decision**.

Right now, the paper gives only accuracy but claims a latency/efficiency trade-off without presenting latency data.

# 5. Be very careful with the allergen/safety claim

This sentence is too strong:

> “This guarantees O(1) time complexity and prevents hallucination of allergens.” 

A deterministic mapping **can prevent generative hallucination**, but it does not guarantee that the allergen information itself is correct.

For example:

```text
Predicted class → database record → allergen information
```

The model can misclassify the food, the mapping can be incomplete, and recipes vary.

A better statement:

> “The deterministic lookup design avoids generative inference of ingredient and allergen information. However, the retrieved information remains dependent on the correctness and completeness of the underlying database.”

That is much more defensible.

Similarly, your “complete compliance with modern data protection regulations” statement is too strong. 

Replace it with:

> “The architecture reduces unnecessary transmission of user images to third-party services by performing inference within the deployed backend. Formal regulatory compliance was not evaluated as part of this study.”

That is academically much safer.

# 6. The confidence/ambiguity algorithm needs proper evaluation

The concept itself is good.

You define:

* `Ptop1 < 0.45` → uncertain
* `Ptop1 - Ptop2 < 0.10` → ambiguous. 

But then you show a “warning system calibration curve” without sufficiently explaining how it was produced. 

A reviewer will ask:

**Why 0.45? Why 0.10?**

You should report something like:

```text
Threshold        Coverage        Accuracy        Rejection rate
0.30             ...
0.40             ...
0.45             ...
0.50             ...
0.60             ...
```

For the ambiguity threshold, similarly evaluate several values:

```text
Delta threshold       Ambiguous cases       Accuracy after filtering
0.05                   ...
0.10                   ...
0.15                   ...
0.20                   ...
```

Then justify the chosen threshold based on measured validation performance.

Otherwise, they look like manually chosen magic numbers.

# 17. The abstract needs rewriting

Your current abstract is good in structure but too product-marketing-heavy. It also makes some claims stronger than your experiments support. 

### Suggested abstract

> **Abstract—** Food recognition from images is challenging due to substantial intra-class variation and visual similarity between food categories. This paper presents FoodLens, an end-to-end deep learning system that combines food classification with confidence-aware prediction and database-based dietary information retrieval. The system uses an ImageNet-pretrained EfficientNetB0 model to classify images into 101 Food-101 categories and integrates data augmentation, two-phase fine-tuning, and test-time augmentation for robust inference. A deterministic confidence and ambiguity module flags low-confidence and closely competing predictions, while a structured database provides ingredient, calorie, and allergen information for recognized classes. The model was evaluated on the official Food-101 test set containing 25,250 images, achieving 73.85% Top-1, 88.44% Top-3, and 92.65% Top-5 accuracy, with a macro F1-score of 73.74%. The trained model is exposed through a Flask REST API and integrated into a Manifest V3 Chrome extension. Experimental analysis further identifies visually similar food categories as the primary source of classification errors. The results demonstrate the feasibility of integrating food recognition and confidence-aware information retrieval into a lightweight web-based application.

That is considerably more academic.
