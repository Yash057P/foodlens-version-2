\begin{abstract}
Image-based dietary assessment requires addressing high intra-class visual variance, subtle inter-class distinctions, and downstream prediction safety. This paper presents FoodLens, an end-to-end deep learning system that couples convolutional food classification with confidence-aware prediction and deterministic dietary information retrieval. FoodLens employs an EfficientNetB0 backbone optimized through a two-phase transfer learning strategy on the 101-class Food-101 benchmark. To guard against uncertain and visually ambiguous inputs, the inference pipeline integrates a 3-way Test-Time Augmentation (TTA) batching scheme and a dual-threshold warning mechanism with confidence threshold $\tau = 0.45$ and ambiguity margin $\Delta = 0.10$. Nutritional and allergen attributes are resolved via deterministic key-indexed database lookup, preventing generative attribute fabrication. Evaluated on the official 25,250-image Food-101 held-out test set, the system achieves 73.85\% Top-1, 88.44\% Top-3, and 92.65\% Top-5 accuracy, with a macro F1-score of 73.74\%. The deployed model requires 4.08M parameters and achieves an average CPU inference latency of 700.04~ms, offering a favorable efficiency trade-off compared to DenseNet121 (7.06M parameters, 1289.39~ms CPU latency) for client-server web and browser extension deployment.
\end{abstract}

\begin{IEEEkeywords}
Food recognition, image classification, convolutional neural networks, transfer learning, EfficientNet, uncertainty estimation, dietary information retrieval.

\section{Introduction}
Automated dietary assessment through computer vision has emerged as an essential tool for personal nutrition tracking, chronic disease management, and public health analytics. However, food recognition presents distinctive visual challenges that set it apart from standard object classification \cite{food101}. Deformable culinary textures, non-rigid geometries, diverse preparation techniques, and varied plating arrangements induce severe intra-class variability. Concurrently, distinct food categories frequently exhibit nearly identical visual appearances---such as beef tartare versus tuna tartare, or steak versus filet mignon---generating substantial inter-class ambiguity.

Traditional computer vision pipelines relied heavily on handcrafted local descriptors such as Scale-Invariant Feature Transform (SIFT) \cite{lowe2004distinctive} and Histograms of Oriented Gradients (HOG) \cite{dalal2005histograms}. While foundational, these representations struggled to capture the complex, non-linear visual distributions characteristic of prepared meals. The advent of deep convolutional neural networks (CNNs) pretrained on large-scale datasets such as ImageNet \cite{deng2009imagenet} revolutionized the domain by enabling hierarchical visual representations. Recent studies have demonstrated the efficacy of transfer learning across various food image classification benchmarks \cite{suddul2023,abiyev2024,razia2024}.

Nevertheless, translating theoretical classification benchmarks into practical, interactive software introduces severe operational challenges. First, standard closed-set softmax classifiers yield forced categorical predictions even when presented with ambiguous or out-of-distribution inputs. Without explicit uncertainty quantification, an overconfident model risks conveying false dietary context. Second, while modern generative multi-modal models can synthesize recipes, they are prone to generative fabrication---inventing nonexistent ingredients or omitting allergens---which poses acute health risks for individuals with dietary restrictions. Furthermore, large generative models impose latency and hardware demands that hinder responsive web deployment.

To resolve these challenges, this paper presents FoodLens, an integrated system combining deep convolutional classification, uncertainty-aware prediction rails, and deterministic nutritional knowledge retrieval. The primary contributions of this work are fourfold:
\begin{enumerate}
    \item \textbf{Empirical Architectural Benchmarking:} We systematically evaluate five candidate architectures on the Food-101 benchmark, establishing that EfficientNetB0 \cite{tan2019efficientnet} delivers a Pareto-efficient balance between classification accuracy, parameter volume, and CPU inference latency relative to deeper backbones such as DenseNet121 \cite{huang2017densely} and ResNet50 \cite{he2016deep}.
    \item \textbf{Dual-Threshold Uncertainty Rails:} We formulate a deterministic confidence and ambiguity scoring mechanism ($\tau = 0.45, \Delta = 0.10$) that flags low-confidence or closely competing predictions, filtering out ambiguous queries and boosting retained Top-1 accuracy to 81.93\%.
    \item \textbf{Deterministic Knowledge Retrieval:} We pair visual classification with a structured key-indexed nutritional database, eliminating generative attribute fabrication while delivering rapid, constant-time ingredient and allergen lookup.
    \item \textbf{Interactive Client-Server Implementation:} We construct and evaluate an end-to-end prototype comprising a stateless Flask REST API backend and a Manifest V3 browser extension client supporting in-browser dietary inspection via side panel interaction.
\end{enumerate}

The remainder of this paper is organized as follows: Section~II surveys related work; Section~III details the system architecture; Section~IV presents the mathematical methodology; Section~V describes the experimental setup; Section~VI presents empirical results and ablation studies; Section~VII discusses deployment, privacy, and system limitations; Section~VIII concludes the paper.

\section{Related Work}
\subsection{Food Recognition Benchmarks and Visual Representations}
Food image analysis has matured from early experiments on constrained datasets to large-scale fine-grained benchmarks. The release of the Food-101 benchmark by Bossard et al.~\cite{food101} established a standard evaluation suite comprising 101,000 images across 101 diverse culinary classes. Early classification approaches employed random forests over handcrafted color and texture patches \cite{food101}. With the ascent of deep learning, convolutional neural networks rapidly superseded handcrafted descriptors \cite{lowe2004distinctive,dalal2005histograms}, leveraging transfer learning from ImageNet \cite{deng2009imagenet}.

Recent investigations have explored diverse architectural enhancements for food recognition. Suddul and Seguin \cite{suddul2023} conducted a comparative evaluation of deep models, emphasizing the necessity of domain adaptation for multi-cuisine robustness. Abiyev and Adepoju \cite{abiyev2024} incorporated self-attention mechanisms to selectively weight discriminative food regions against cluttered table backgrounds. Razia Sulthana et al.~\cite{razia2024} paired convolutional feature extractors with natural language processing to extract structured recipe components from classified food images.

\subsection{Efficient Deep Learning Architectures}
Deploying convolutional vision models in client-server and edge environments requires balancing parameter count, memory footprint, and execution latency. Residual Networks (ResNet) \cite{he2016deep} introduced identity shortcut connections to overcome the vanishing gradient problem, allowing the training of substantially deeper models. MobileNetV2 \cite{sandler2018mobilenetv2} introduced inverted residual blocks and depthwise separable convolutions to dramatically cut floating-point operations (FLOPs), optimizing execution on mobile processors. DenseNet \cite{huang2017densely} established dense connectivity patterns where each layer receives direct feature inputs from all preceding layers, maximizing feature reuse at the expense of memory-bandwidth overhead during concatenation.

Tan and Le \cite{tan2019efficientnet} proposed EfficientNet, introducing a principled compound scaling method that uniformly scales depth, width, and input resolution using fixed scaling coefficients. EfficientNetB0 achieves competitive classification accuracy while utilizing a fraction of the parameters demanded by conventional architectures. Subsequently, EfficientNetV2 \cite{tan2021efficientnetv2} further refined training velocity and parameter efficiency through fused convolutional blocks. The availability of standardized pretrained backbones via Keras Applications \cite{kerasapps} enables systematic cross-architectural benchmarking.

\subsection{Dietary Information Retrieval and Calibration}
A critical requirement in practical dietary software is the reliable mapping of recognized classes to nutritional content. While multi-modal vision-language models can describe culinary imagery, their generative nature makes them susceptible to generative fabrication of ingredients or omission of critical allergens. In contrast, deterministic retrieval systems map predicted category labels to curated nutrient databases.

A fundamental vulnerability of deep neural networks is probability miscalibration: modern architectures often produce overconfident predictions even on erroneous or out-of-distribution samples \cite{guo2017}. To mitigate this risk without requiring extensive model recalibration, threshold-based filtering policies can reject low-confidence classifications and highlight ambiguous class pairs before downstream retrieval occurs.

\section{System Architecture}
FoodLens is implemented as a decoupled client-server architecture designed to provide responsive in-browser dietary assistance while maintaining complete server-side model encapsulation.

\subsection{End-to-End Processing Pipeline}
The system pipeline operates across five modular stages:
\begin{enumerate}
    \item \textbf{Image Acquisition:} The user selects or right-clicks a food image within the browser client.
    \item \textbf{Client Request Dispatch:} The browser extension extracts image bytes and dispatches an asynchronous HTTP POST request to the backend service.
    \item \textbf{Inference and Augmentation:} The server preprocesses the payload, forms a 3-way Test-Time Augmentation batch, and performs an EfficientNetB0 forward pass.
    \item \textbf{Threshold and Uncertainty Evaluation:} The resulting posterior distribution is evaluated against confidence and ambiguity threshold rails.
    \item \textbf{Knowledge Base Query and UI Render:} The Top-3 candidate labels are resolved against a curated nutritional database, and a structured JSON response is transmitted to the client for side panel rendering.
\end{enumerate}

\subsection{Backend REST API Service}
The computational engine is implemented as a Python microservice using the Flask framework, exposing the primary inference route \texttt{/api/predict}. To minimize initialization latency and memory consumption, the trained Keras model is loaded once during server startup with graph compilation disabled (\texttt{compile=False}).

The backend operates strictly statelessly. Upon receiving an image payload, raw image bytes are decoded in volatile memory into a PIL image object, converted to a NumPy array, and processed into a normalized batch tensor. Following prediction generation and database query execution, memory references to the input image tensors are immediately released for garbage collection. Cross-Origin Resource Sharing (CORS) is enabled to permit authenticated extension queries while rejecting unauthorized domains.

\subsection{Browser Extension Client}
The user interface is engineered as a Manifest V3 Chrome Extension. It leverages the Chrome \texttt{contextMenus} API to allow seamless right-click inspection of food imagery embedded across web pages. Upon activation, the extension opens a dedicated side panel using the Chrome \texttt{sidePanel} API, providing persistent, non-intrusive visualization alongside active browsing tabs.

\subsection{Curated Dietary Knowledge Base}
Rather than delegating nutritional attribution to generative language models, FoodLens queries a structured local JSON database (\texttt{ingredients.json}) covering all 101 Food-101 categories. Each entry contains:
\begin{itemize}
    \item Estimated caloric value (kcal per typical serving);
    \item Standard culinary category (e.g., dessert, soup, poultry);
    \item Primary common ingredients;
    \item Standard allergen tags (e.g., dairy, gluten, nuts, seafood);
    \item Non-clinical dietary informational disclaimer.
\end{itemize}
Because class labels serve as direct hash keys into the database dictionary, nutritional attribute retrieval operates with constant-time complexity, introducing negligible computational overhead relative to the convolutional forward pass.

\section{Methodology}
\subsection{Classification Backbone and Feature Extraction}
The visual classification backbone utilizes EfficientNetB0 \cite{tan2019efficientnet}, selected for its high parameter efficiency. EfficientNet relies on Mobile Inverted Bottleneck Convolutions (MBConv) enhanced with squeeze-and-excitation optimization. Given an input tensor $\mathbf{x} \in \mathbb{R}^{224 \times 224 \times 3}$, the backbone extracts a 1280-dimensional feature embedding $\mathbf{f} \in \mathbb{R}^{1280}$ via Global Average Pooling:
\begin{equation}
\mathbf{f} = \text{GAP}(\text{EfficientNetB0}(\mathbf{x}))
\end{equation}
The classification head consists of an intermediate dense transformation with ReLU activation, a dropout regularization layer ($\text{rate} = 0.3$) to suppress feature co-adaptation, and a linear output layer projecting into unnormalized logit space:
\begin{equation}
\mathbf{z} = \mathbf{W}_2 \cdot \text{Dropout}_{0.3}(\sigma(\mathbf{W}_1 \mathbf{f} + \mathbf{b}_1)) + \mathbf{b}_2
\end{equation}
where $\mathbf{z} \in \mathbb{R}^{K}$ with $K = 101$.

\subsection{Mathematical Formulation}
The unnormalized logits $\mathbf{z} = [z_1, z_2, \dots, z_K]^T$ are converted into a normalized posterior probability distribution over the $K = 101$ target classes using the softmax activation function:
\begin{equation}
P_i(\mathbf{x}) = \frac{\exp(z_i)}{\sum_{j=1}^{K} \exp(z_j)}, \quad i \in \{1, \dots, K\}
\label{eq:softmax}
\end{equation}
where $P_i(\mathbf{x})$ denotes the posterior probability assigned to class $i$, satisfying $\sum_{i=1}^{K} P_i(\mathbf{x}) = 1$ and $P_i(\mathbf{x}) \ge 0$.

During training, network parameters are optimized by minimizing the multi-class categorical cross-entropy loss function:
\begin{equation}
\mathcal{L} = -\sum_{i=1}^{K} y_i \log P_i(\mathbf{x})
\end{equation}
where $\mathbf{y} \in \{0, 1\}^K$ represents the one-hot encoded ground-truth class label vector.

\subsection{Training Data Augmentation}
To mitigate overfitting on fine-grained culinary visual features, training images are processed through GPU-accelerated sequential data augmentation layers embedded directly within the input graph:
\begin{itemize}
    \item Random horizontal flipping ($\text{factor} = 0.5$);
    \item Random rotations up to $\pm 10\%$ ($\pm 36^{\circ}$);
    \item Random zoom scaling up to $\pm 10\%$.
\end{itemize}
This dynamic transformation exposes the network to substantial spatial and framing diversity across training iterations without incurring disk I/O penalties.

\subsection{Two-Phase Transfer Learning Protocol}
To effectively transfer features from ImageNet \cite{deng2009imagenet} without destabilizing pretrained convolutional representations, we implement a two-phase transfer learning schedule:
\begin{itemize}
    \item \textbf{Phase 1 (Feature Extraction):} All convolutional backbone weights are frozen ($\text{trainable} = \text{False}$). Only the classification head parameters (176,997 trainable weights) are optimized using the Adam optimizer \cite{kingma2014adam} with an initial learning rate $\eta = 1 \times 10^{-3}$ for up to 10 epochs.
    \item \textbf{Phase 2 (Fine-Tuning):} The top 20 layers of the EfficientNetB0 backbone are unfrozen, yielding 1,527,957 trainable parameters. Training proceeds with a reduced learning rate of $\eta = 1 \times 10^{-5}$ managed by a \texttt{ReduceLROnPlateau} scheduler (decay factor 0.2, patience 1, minimum learning rate $1 \times 10^{-7}$) and early stopping monitored on validation loss.
\end{itemize}

\subsection{Confidence and Ambiguity Detection Rails}
To guard against uncalibrated overconfidence on out-of-distribution or visually ambiguous inputs, FoodLens enforces a deterministic dual-threshold filtering policy prior to output delivery:
\begin{enumerate}
    \item \textbf{Low-Confidence Threshold ($\tau$):} Let $P_{(1)} = \max_{i} P_i(\mathbf{x})$ denote the maximum softmax probability. If
    \begin{equation}
    P_{(1)} < \tau \quad (\tau = 0.45)
    \end{equation}
    the query is flagged as ``Uncertain'', prompting the user to provide a clearer or more centered photograph.
    \item \textbf{Ambiguity Margin ($\Delta$):} Let $P_{(1)}$ and $P_{(2)}$ denote the highest and second-highest predicted probabilities. If
    \begin{equation}
    P_{(1)} - P_{(2)} < \Delta \quad (\Delta = 0.10)
    \end{equation}
    the query is flagged as ``Ambiguous'', signaling competing visual hypotheses (such as distinct meat preparations or visually similar soups).
\end{enumerate}

\begin{figure}[htbp]
\centering
\includegraphics[width=0.88\columnwidth]{figures/fig_warning_curve.pdf}
\caption{Threshold calibration curve illustrating coverage rate and retained Top-1 accuracy as a function of the minimum confidence threshold $\tau$.}
\label{fig:warning}
\end{figure}

As illustrated in Fig.~\ref{fig:warning}, setting $\tau = 0.45$ establishes an effective operational compromise, pruning low-confidence errors while preserving high prediction coverage.

\subsection{Test-Time Augmentation (TTA)}
To bolster prediction stability against off-center plating and framing variations without altering model architecture, the inference pipeline employs a 3-way Test-Time Augmentation scheme. For an incoming input image $\mathbf{x}_{\text{orig}}$, three representations are constructed:
\begin{enumerate}
    \item $\mathbf{x}_1 = \text{Resize}_{224}(\mathbf{x}_{\text{orig}})$: Standard bilinearly resized image (${224 \times 224}$);
    \item $\mathbf{x}_2 = \text{Flip}_h(\mathbf{x}_1)$: Horizontal mirror reflection;
    \item $\mathbf{x}_3 = \text{Resize}_{224}(\text{Crop}_{0.9}(\mathbf{x}_{\text{orig}}))$: Central 90\% crop simulating camera zoom.
\end{enumerate}
These images are stacked into a batch tensor $\mathbf{X}_{\text{batch}} \in \mathbb{R}^{3 \times 224 \times 224 \times 3}$ and evaluated in a single forward pass:
\begin{equation}
\bar{P}_i = \frac{1}{3} \sum_{m=1}^{3} P_i(\mathbf{X}_{\text{batch}}^{(m)})
\end{equation}
Averaging the posterior distributions suppresses view-dependent prediction variance.

\section{Experimental Setup}
\subsection{Dataset Partitioning Protocol}
Our experimental investigation is conducted on the Food-101 benchmark \cite{food101}, comprising 101 categories and 101,000 total images. The codebase encompasses two distinct experimental tracks:
\begin{itemize}
    \item \textbf{Track A (Production 101-Class Model):} Trained on the complete 101-class dataset. The official training partition (75,750 images) was split using an 85/15 stratified ratio into 64,387 training images and 11,363 validation images. The official held-out test partition of 25,250 images (exactly 250 images per class) was quarantined throughout training and evaluated once to establish unbiased test metrics.
    \item \textbf{Track B (Controlled 20-Class Baseline Suite):} To systematically benchmark diverse candidate backbones under identical computational conditions, a controlled 20-class subset was established (\texttt{config.py}) spanning 20 visually diverse cuisines: \textit{pizza, sushi, hamburger, ramen, ice cream, apple pie, french fries, fried rice, samosa, chicken curry, pad thai, steak, caesar salad, tiramisu, hot dog, dumplings, grilled cheese sandwich, macaroni and cheese, baklava,} and \textit{pho}. Each class was partitioned into 600 training images (12,000 total), 150 validation images (3,000 total), and 250 test images (5,000 total) using a fixed random seed.
\end{itemize}

\subsection{Implementation and Hyperparameters}
Input images were decoded and resized to ${224 \times 224 \times 3}$ pixels. For EfficientNetB0, raw $[0, 255]$ pixel values were supplied directly, leveraging the architecture's internal normalization layers. Training was conducted using a batch size of 16 for Track A (32 for Track B). Optimization was performed using the Adam algorithm \cite{kingma2014adam} with standard parameters ($\beta_1 = 0.9, \beta_2 = 0.999$). To accelerate training throughput and reduce GPU memory consumption, mixed precision arithmetic (\texttt{mixed\_float16}) was utilized.

\subsection{Hardware and Software Specifications}
The training pipeline was executed in Python 3.12 utilizing Keras 3.15 and TensorFlow 2.21 on an NVIDIA GPU workstation. Deployment latency benchmarks were measured on a host x86\_64 CPU environment supporting oneDNN and AVX2 vector instructions. Inference was executed in single-threaded mode with batch size 1, accurately simulating real-world CPU-based cloud hosting conditions.

\subsection{Evaluation Metrics}
Model performance is quantified using standard multi-class classification metrics: Top-1 Accuracy, Top-3 Accuracy, Top-5 Accuracy, and macro-averaged Precision, Recall, and F1-score across all supported categories:
\begin{equation}
\text{Macro-F1} = \frac{1}{K} \sum_{k=1}^{K} \frac{2 \cdot \text{Prec}_k \cdot \text{Rec}_k}{\text{Prec}_k + \text{Rec}_k}
\end{equation}

\section{Deployment, Privacy, and Limitations}
While FoodLens demonstrates the feasibility of interactive food recognition, a rigorous assessment of deployment, privacy, and systemic limitations is essential for responsible software engineering.

The system is subject to several fundamental operational and clinical limitations:
\begin{enumerate}
    \item \textbf{Closed-Set Classification Constraint:} The model is strictly constrained to the 101 categories in the Food-101 taxonomy. When presented with non-food imagery, unseen dishes, or out-of-distribution inputs, the system cannot infer novel classes and relies entirely on the confidence threshold ($\tau = 0.45$) for rejection.
    \item \textbf{Single-Label Formulation:} The current pipeline assumes an input image contains a single predominant food item. It cannot decompose mixed plates, banquets, or composite meals containing multiple distinct dishes.
    \item \textbf{Culinary Variance and Recipe Deviations:} Nutritional values and ingredients retrieved from the database represent standardized culinary profiles. They cannot account for ingredient variability, recipe modifications, custom cooking oils, or regional variations in preparation.
    \item \textbf{Database Dependency and Error Propagation:} Downstream nutritional retrieval is strictly dependent on visual classification accuracy and database completeness. A misclassification inevitably propagates into incorrect dietary estimates.
    \item \textbf{Clinical Safety and Medical Disclaimer:} The nutritional values and allergen safety alerts provided by FoodLens are informational estimates intended solely for general consumer awareness. They do NOT constitute clinical diagnosis, certified dietary prescriptions, or medical assurances. The system cannot assure protection against life-threatening food allergies or anaphylaxis.
\end{enumerate}

\subsection{Deployment Considerations and Runtime Efficiency}
The FoodLens pipeline is packaged within a lightweight Docker container encapsulating the Flask WSGI server, Keras runtime, and dependencies. In our benchmarks, single-image inference requires 700.04~ms on host CPU, ensuring prompt responsiveness within the Chrome extension side panel. Preloading model weights during server boot eliminates cold-start penalties during active sessions.

\subsection{Privacy and Stateless Data Handling}
To minimize privacy exposures associated with transmitting personal imagery to third-party commercial cloud vision APIs, FoodLens operates on a self-hosted backend. User images are processed statelessly in volatile RAM and are deallocated immediately upon payload transmission. No user imagery is cached to persistent disk, stored in databases, or repurposed for training. While this stateless processing architecture reduces data retention risks, formal statutory compliance under frameworks such as GDPR or CCPA was not independently audited and would require comprehensive legal and organizational procedures.

\section{Conclusion}
This paper presented FoodLens, an end-to-end deep learning system for food recognition that couples convolutional classification with confidence-aware prediction rails and deterministic dietary information retrieval. By benchmarking candidate architectures, we identified EfficientNetB0 as an optimal balance between accuracy (73.85\% Top-1, 88.44\% Top-3 on 25,250 Food-101 test images) and CPU execution latency (700.04~ms), outperforming DenseNet121 in computational efficiency. The incorporation of a 3-way Test-Time Augmentation scheme and a dual-threshold warning mechanism ($\tau = 0.45, \Delta = 0.10$) effectively flags ambiguous queries, elevating retained Top-1 accuracy to 81.93\%. Furthermore, deterministic database retrieval prevents generative ingredient fabrication. Future work will investigate open-set rejection for non-food inputs, multi-dish segmentation for mixed plates, and edge model quantization for native mobile deployment.
